create_react_agent with post_model_hook will not inject state/store to tool calls

### Example Code

```python
from typing import Annotated
from langgraph.prebuilt import create_react_agent, InjectedState
from langchain_core.tools import tool
from langchain_core.language_models import FakeMessagesListChatModel
from langchain_core.messages import AIMessage, ToolCall
from langgraph.errors import GraphRecursionError
from langgraph.checkpoint.memory import MemorySaver


class FakeMessagesListChatModelWithToolCalls(FakeMessagesListChatModel):
    def bind_tools(
        self,
        tools,
        *,
        tool_choice=None,
        **kwargs,
    ):
        return self


the_news = "News are boring."


@tool("read_the_news", description="Read the news")
def read_the_news(
    state: Annotated[dict, InjectedState],
):
    return the_news


model = FakeMessagesListChatModelWithToolCalls(
    responses=[
        AIMessage(
            content="I will check the news.",
            tool_calls=[ToolCall(name="read_the_news", args={}, id="1")],
        )
    ]
)


checkpointer = MemorySaver()

agent_ok = create_react_agent(
    model=model,
    tools=[read_the_news],
    checkpointer=checkpointer,
)

config = {"configurable": {"thread_id": "ok"}, "recursion_limit": 4}
response = agent_ok.invoke({"messages": ["What's on the news?"]}, config)
print("agent_ok:")
print(response["messages"][-1].content == the_news)  # True


def post_model_hook(state):
    return


agent = create_react_agent(
    model=model,
    tools=[read_the_news],
    post_model_hook=post_model_hook, # <-- This makes the difference
    checkpointer=checkpointer,
)

config = {"configurable": {"thread_id": "not_ok"}, "recursion_limit": 4}
try:
    response = agent.invoke({"messages": ["What's on the news?"]}, config)
except GraphRecursionError as e:
    messages_before_crash = agent.get_state(config).values["messages"]
    print("agent_not_ok:")
    print(messages_before_crash[-1].content)
```

### Description

When using the `post_model_hook` in `create_react_agent` the injection of state/store into the tool calls is not performed.
Any reliance on state in a tool for such an agent will fail the pydantic input args validations.

Cause of the problem is here:
In langgraph/prebuilt/chat_agent_executor.py
The code of [`post_model_hook_router`](https://github.com/langchain-ai/langgraph/blob/2553ae0b877c58beb8947db70336c008d7c7ea23/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L709) decides if a tool execution is required, and will use `Send` to route to the tool node like so:
```python
return [Send("tools", [tool_call]) for tool_call in pending_tool_calls]
```

Comparing that with the [`should_continue`](https://github.com/langchain-ai/langgraph/blob/2553ae0b877c58beb8947db70336c008d7c7ea23/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L632) implementation, When there is no "post_model_hook" setup it will `Send` to the tools node like so:
```python
tool_calls = [
    tool_node.inject_tool_args(call, state, store)  # type: ignore[arg-type]
    for call in last_message.tool_calls
]
return [Send("tools", [tool_call]) for tool_call in tool_calls]
```

So, when the hook is setup you get the flow:
agent -> should_continue -> post_model_hook -> post_model_hook_router -> tools
And without you get:
agent -> should_continue -> tools

The first, will neglect to inject a state/store and the latter will.
I believe this is a bug.
Ideally, there will be a single "send to tools" implementation which both routers should use.
